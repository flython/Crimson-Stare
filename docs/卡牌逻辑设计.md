## 1. 目标与边界

| 项 | 内容 |
|---|---|
| **目标** | 把 21 张角色牌 + 52 张黑市牌的效果**全部**注册到引擎;卡池数据从 xlsx 一次性转换,server 启动时载入 |

## 2. 总体架构

```
┌──────────────┐    ┌─────────────────┐    ┌──────────────────┐
│ xlsx 模板     │ →  │ 转换脚本 build  │ →  │ config/cards/*.json│
│ (飞飞手工)    │    │ (Node/TS)       │    │ (git 提交)        │
└──────────────┘    └─────────────────┘    └──────────────────┘
                                                     ↓ 启动时 read
                                              ┌──────────────────┐
                                              │ server (注入)     │
                                              │ config.ts +       │
                                              │ cardPool.ts       │
                                              └──────────────────┘
                                                     ↓ createGame
                                              ┌──────────────────┐
                                              │ engine 纯函数     │
                                              │ - state.ts        │
                                              │ - effects.ts      │
                                              │ - effectsRegistry │ ← 硬编码注册全量
                                              └──────────────────┘
```

**两个独立关注点**:
- **数据管道**:xlsx → JSON,纯静态(可在 CI 跑)。输出物提交 git。
- **效果注册**:TS 代码,手写。每个卡牌 ID 对应一个或多个 `EffectDef`,挂到引擎注册表。

## 3. 数据管道

### 3.1 转换脚本位置与脚本命令

- **位置**:`packages/card-data/`(新建,TS,与 engine 同栈)
- **依赖**:`xlsx`(SheetJS)+ `zod`(schema 校验)
- **命令**:
  - `npm run cards:build` — 读 `config/card-pool-template.xlsx` → 输出 `config/cards/{roles,market,fate,events}.json` + `config/cards/manifest.json`
  - `npm run cards:check` — 校验模式,只跑校验不写文件(CI 友好)
- **运行时**:`tsx` 直接跑(无需 build)

### 3.2 输出 JSON 结构(已与 engine 类型对齐)

```ts
// config/cards/manifest.json
{
  "version": "2026-08-30",
  "generatedAt": "2026-08-30T01:24:00Z",
  "counts": { "roles": 21, "market": 52, "fate": 15, "events": 36 }
}

// config/cards/roles.json
interface CardDef {
  id: string;            // "01" / "001" / "F1" / "E1"
  name: string;
  /** 类型元数据 */
  category: "role" | "market" | "fate" | "event";
  subtype?: string;      // 黑市: "强化芯片" | "秘密交易" | "道具"; 命运: "基础" | "高级"
  count: number;         // 牌池中同名牌的张数(默认 1,黑市常见 2)
  price?: number;        // 黑市牌价
  yellowBorder?: boolean;// 简易模式可用(黑市)
  simpleOnly?: boolean;  // 简易模式可用(角色)
  colorTag?: string;     // 牌型绿 / 容错蓝 / 互动暗红 / 经济 / 删牌 ...
  /** 引擎触发点(从「触发时机」列展开) */
  triggers: { phase: PhaseId; timing: Timing; }[];
  /** 效果注册表 key;缺失则引擎降级为「白板 + log」 */
  effectId?: string;     // "role:01" / "market:001:during:duel" 等
  effectText: string;    // 卡面原文,UI 展示;逻辑不解析
  image: string;         // "assets/cards/role/01.png" 等
  /** 仅命运牌使用 */
  fateData?: {
    dealerHand: string;       // "5♣ 6♣ 7♦ 8♦ ?♠"
    diceMapping: string;      // "A,2,3 → 高牌; 4 → 顺子; 5,6 → 对子"
  };
}
```

### 3.3 转换脚本职责(伪代码)

```ts
// packages/card-data/src/build.ts
const ROLE = "角色牌", MARKET = "黑市牌", FATE = "命运牌", EVENT = "事件牌";
const sheet = workbook.Sheets[name];

const rows = parseSheet(sheet, COLS[name]);   // 必填列校验
validate(rows, RULES[name]);                  // 唯一性 / 枚举 / 数值
const defs = rows.map(rowToCardDef);          // 字段映射
group(defs, "yellowBorder|simpleOnly")        // 简易模式标记保留

writeJson(`config/cards/${name}.json`, defs);
writeJson(`config/cards/manifest.json`, manifest);
```

**校验规则**(硬错=拒绝;警告=输出但继续):
- 硬:ID 唯一、必填列存在、image 非空、count ≥ 1、price ≥ 0
- 硬:触发时机列每段必须是 `PhaseId` + 可选 `前/结束`;非法值报错并指出
- 警:图片文件不存在(可能素材还没到位)、未识别列被忽略
- 警:同 ID 多张卡(应只 1 行,数量用 count 列)

### 3.4 启动时载入(server)

```ts
// packages/server/src/cardPool.ts
import { readFileSync } from "node:fs";
import { join } from "node:path";
import type { CardDef } from "@crimson-stare/engine/cardPool";

export function loadCardPool(configDir: string): CardPool {
  const dir = join(configDir, "cards");
  const manifest = JSON.parse(readFileSync(join(dir, "manifest.json"), "utf8"));
  return {
    manifest,
    roles:  load<CategoryDir>(join(dir, "roles.json")),
    market: load(join(dir, "market.json")),
    fate:   load(join(dir, "fate.json")),
    events: load(join(dir, "events.json")),
  };
}
```

`server/src/index.ts` 启动时调 `loadCardPool(process.env.CONFIG_DIR)`,挂到 WS 协议层;**`createGame(config, pool)`** 把 pool 注入 engine(与 `GameConfig` 同模式,见 `core/config.ts`)。

## 4. 效果系统:硬编码注册表(全量)

### 4.1 EffectDef 组织(以角色牌为例)

```ts
// packages/engine/src/effects/roles.ts
import { registerEffect } from "../core/effects.js";

export function registerRoleEffects(): void {
  // 模式:「实现一次,注册多条」
  // 校准器 +N 系列 = 同一个 effect 工厂
  for (const n of [1, 2, 3, 4]) {
    registerEffect({
      id: `market:00${n}:during:duel`,  // 校准器 +N
      source: "blackMarket",
      phase: "duel",
      timing: "during",
      run: (state, ctx) => applyPermanentRankBoost(state, ctx, n),
    });
  }

  // 角色牌 01 赌场荷官:【结算】你的牌型总点数+20
  registerEffect({
    id: "role:01:after:settle",
    source: "character",
    phase: "settle",
    timing: "after",
    run: (state, ctx) => {
      const me = state.players.find(p => p.id === ctx.playerId);
      me.chips += 20;
      state.log.push({ ...logBase(state), text: `${me.name}【赌场荷官】+20 血筹` });
    },
  });
  // ...
}
```

**效果原语库**(`packages/engine/src/effects/primitives.ts`):
> 每个原语是一个 `EffectContext → void`,封装常见的「增/减血筹、增/减车票、删除牌、移动牌、修改点数、修改花色、修改牌型、修改 swapLeft、暂停技能、暂停强化芯片、掷骰、随机弃」等。所有 EffectDef.run 内部调用原语,**杜绝重复逻辑**。

例:
```ts
export const gainChips = (n: number): EffectBody =>
  (state, ctx) => getPlayer(state, ctx).chips += n;

export const disableMyChipsThisTurn = ...
export const rerollRandomCard = ...
export const moveCardTop = ...
```

### 4.2 触发时机列的映射

`触发时机` 列(角色/黑市/事件)值如 `对决;结算;购买` → 解析为多条 `EffectDef` 共享同一 `run`:

| 模板取值 | 引擎 (phase, timing) |
|---|---|
| 抽牌 / 换牌 / 出牌 / 对决 / 结算 / 购买 / 删牌 / 重整 | (phase, "during") |
| …阶段前 | (phase, "before") |
| …阶段结束 | (phase, "after") |
| 常驻 | 不挂时机,reducer 持续读取 characterId/items 状态 |
| 立即 | 由事件/购买 reducer 立即调用,不进时间点框架 |
| 多值如 `对决;结算` | 同 id 注册多条,共享同一 run 工厂 |

**多时机合并**:同一卡牌多 phase 注册条目共享 `run` 工厂(传 `phase` 参数),不必为每个时机重写。

### 4.3 全量 21 角色 + 52 黑市牌注册清单

> 工作分解:每张卡 = 1 个 EffectDef(或同模式多 Def)。详见 §7 实施清单。

**简易模式过滤**:`createGame(config, pool, { simple: true })` 时从 `pool.market` 只取 `yellowBorder === true`(24 张),`pool.roles` 只取 `simpleOnly === true`(4 张)。**非简易模式(M3+)**全量可用。

### 4.4 降级:注册表缺失时

```ts
function getOrPlaceholder(effectId: string): EffectDef {
  const def = registry.get(effectId);
  if (def) return def;
  return PLACEHOLDER_EFFECT;  // 无效果,仅 log "效果未实现:<id>"
}
```

玩家在 UI 上仍可购买/抽取;日志提示「该牌效果未实现」;**未来注册后立即生效**。

## 5. 交互机制(M2 关键新增)

### 5.1 最小交互原语

效果要选目标/选牌/掷骰时,**挂起等玩家输入**。设计 3 个原语 + 1 个 Action 队列:

```ts
// packages/engine/src/effects/interactive.ts
export type PendingPrompt =
  | { kind: "choosePlayer"; effectId: string; candidates: string[]; /* 玩家 id 列表 */ }
  | { kind: "chooseCard";   effectId: string; candidates: Card[];   from: ZoneId;  }
  | { kind: "rollDice";     effectId: string; /* 引擎直接调 rng.nextInt(6)+1,无需玩家操作 */ };

// GameState 新增字段
interface GameState {
  // ... 现有字段
  pendingPrompt: PendingPrompt | null;  // 同一时刻最多 1 个挂起
}
```

**Action 新增**(server 收到玩家输入后,reducer 消费):
```ts
type Action =
  | ... 现有
  | { type: "resolvePrompt"; payload: unknown };  // 由 prompt.kind 决定 payload 形状
```

**reducer 调度**:
- `runTimingQueue` 遇到「需要交互」的效果 → 构造 `PendingPrompt` 写入 state → **return** 等待客户端 `resolvePrompt` action
- 客户端收到 `stateUpdate` 含 `pendingPrompt` → 渲染对应 UI(选目标/选牌)→ 用户操作 → 发 `resolvePrompt` → reducer 继续执行原效果
- `rollDice` 实际不需要客户端 UI,引擎服务端掷骰即可,直接返回结果

### 5.2 简易模式首批用到的交互(M2 范围)

24 张黄边黑市牌 + 4 角色里**真正需要交互的极少**:
- 暴力删除(选对手)→ `choosePlayer`
- 廉价删除(选自己弃牌区 0-2 张)→ `chooseCard`
- 廉价删除的「每位对手可删 1 张」→ 需多玩家 prompt(简化:仅自己删 2 张,对手环节先不做,M3 再补)
- 黑客(21 角色)初始构筑 = 全牌库挑 8 张删 → M2 是否做(非简易角色,优先级低)

**结论**:M2 实现 `choosePlayer` + `chooseCard` 两个原语 + `resolvePrompt` action + 4 角色 + 24 黄边黑市效果,**全部覆盖**;其余全量 52 牌按需补 handler(本轮设计已能承接)。

### 5.3 复杂交互(M3+ 保留)

暗拍/拍卖/轮流掷骰/猜测/「会赢的」宣告 → 留待 M3,在现有 `PendingPrompt` 扩展 `kind` 即可,框架不需重写。

## 6. UI 交互设计(支持交互)

### 6.1 触发流程

```
server 推送 stateUpdate → 含 pendingPrompt
         ↓
web 端 prompt 渲染:
  - choosePlayer → 高亮所有 candidates 玩家头像/座位,点击 → 发 resolvePrompt
  - chooseCard   → 高亮手牌/弃牌区对应牌,点击 → 发 resolvePrompt
  - rollDice     → 不需要,server 直接出结果
         ↓
server 收到 resolvePrompt → 校验候选 → reducer 继续
```

### 6.2 UI 组件新增(`packages/web/src/components/`)

| 组件 | 职责 |
|---|---|
| `<TargetPicker>` | 选玩家:列出所有候选,点击高亮 + 确认 |
| `<CardPicker>` | 选牌:从指定 zone 高亮,支持多选(checkbox 风格) |
| `<DiceRollAnimation>` | 掷骰动画:即使服务端掷,前端也播 0.5s 动画再出结果 |
| `<EffectLog>` | 每回合效果日志(已经存在,扩展) |
| `<PendingPromptBanner>` | 顶部横幅提示「等待 X 玩家选择目标/选牌」 |

### 6.3 与现有 UI 的衔接

- `web/src/` 现有 Vite + TS + 触屏/鼠标适配,新组件走同样样式系统
- 暗色牌桌、基色 `#e9404b / #583c42 / #ffc840` 保留
- 占位卡图片失败回退逻辑已有,新交互组件复用占位风格

### 6.4 与「效果文本」展示的关系

- 选目标/选牌时,**效果原文**继续在卡牌悬浮/侧边栏展示,玩家清楚知道自己在响应哪个效果
- 多 step prompt(罕见)按顺序弹多个 picker,UI 顶部显示进度

## 9. 风险与遗留

| 风险 | 应对 |
|---|---|
| xlsx 列名/列序后续会改 | 转换脚本按**列名**识别(issue 06 已定),新增列加白名单 |
| 效果文本含未覆盖的奇效(如「猜测本回合特权证玩家」) | 抽象成新原语;实在不行就降级「无效果 + log」 |
| 简易模式「每位对手可删 1 张」等多玩家 prompt 复杂 | M2 暂简化(只删自己的 2 张,对手删牌留 M3) |
| 21 角色效果编写工作量大(每张独立看规则) | 模式复用:把同类效果写成工厂,模板化 |
| server 启动时若 JSON 损坏 | `loadCardPool` 抛错并退出(server crash,不是静默错) |
| JSON 与 TS 类型不同步 | 转换产物在生成时用 zod 校验 + 与 engine 类型做 `expectType` |
