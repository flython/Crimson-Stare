# 13 - M2.4 交互机制（效果挂起）

Type: task
Status: resolved
Blocked by: 09, 10

## Question

效果需要玩家输入（选目标/选牌）时如何挂起与恢复：`GameState.pendingPrompt` + `resolvePrompt` Action + `choosePlayer / chooseCard` 原语（grilling Q4 已确认最小交互原语）。

## Answer

已落地（2026-08-30，engine 46 测试全过，其中交互 9 用例）：

- **state**：`PendingPrompt` 类型（`choosePlayer | chooseCard`，含 effectId/playerId/candidates/from/promptText），`GameState.pendingPrompt: PendingPrompt | null`。
- **两段式效果**：`EffectDef.resolve?: (state, ctx, choice) => void`；run 写入 pendingPrompt 挂起，`runTimingQueue` 遇挂起 break；玩家 `resolvePrompt` 后 reducer 调 resolve 继续。简单交互（选玩家/选牌）不携带中间状态，复杂多步交互留 M3。
- **Action**：新增 `{ type: "resolvePrompt"; playerId; choice }`；reduce 入口挂起门禁——pendingPrompt 非空时只接受目标玩家的 resolvePrompt，其余 Action 拒绝。
- **校验**：`validateChoice`（choosePlayer 单值∈候选；chooseCard 数组、无重复、∈候选）。
- **超时托管**：`autoResolve(state)`（choosePlayer 随机候选、chooseCard 默认不选），`GameConfig` 新增 `promptTimeoutSec: 60` + `timeoutPolicy: "auto" | "strict"`（server 定时器接线留 15）。
- **可见性**：`redactState` 裁剪 pendingPrompt——目标玩家见完整候选，其余玩家只见 `{ waitingFor, promptText }`（chooseCard 候选牌 id 是私密的）。
- **测试**：挂起与恢复（选玩家/选牌）、挂起门禁、等待者校验、非法/重复选择拒绝、autoResolve、redact 可见性。
- **遗留**：server WS 的 resolvePrompt 消息接入 + 超时定时器 + 协议文档更新（docs/protocol.md），随 15 号票据联调时落地。
