# 02 - 引擎核心抽象定型

Type: prototype
Status: ready-for-human
Blocked by: 01

## Question

engine 包的核心抽象必须在写第一行业务逻辑前定型，否则 8 阶段流程、宣告排队、效果时间点全会返工：

- 状态形状：一局游戏的可序列化 state 长什么样（玩家区、抽牌堆/弃牌堆/删牌区/出牌区/黑市区、阶段游标、特权证归属）？私密信息（手牌、弃牌区）如何在 state 中标记可见性？
- Action/Reducer 模型：客户端操作如何表达（换牌、选牌、宣告选择、购买……）？是否可重放（RNG 必须注入、种子可记录）？
- 时间点框架：阶段前/中/后钩子如何注册与触发？同时机冲突按特权证→顺时针结算的实现形状？
- 效果注册表接口：`效果ID → (state, ctx) => 变更` 的签名与优先级链（事件牌>角色技能>黑市牌>规则书）如何挂接？
- 产出：engine 核心类型与最小可跑的骨架 reducer（不实现完整规则），供 04/05/06 票据引用。需与飞飞过一遍抽象是否成立。

## Answer

**四块核心抽象已落地为可运行代码（engine/src/core/ + game/whiteboard.ts），25 测试全过，待飞飞确认后标记 resolved。**

### 1. 状态形状（core/state.ts）
- `GameState` 完全可 JSON 序列化；`players[]` 按座位顺时针排列（顺时针规则直接用数组下标运算）。
- 玩家区域：`draw / hand / discard / play / deleted` 五区 + `chips`（芯片挂载：牌实例id→黑市牌id）+ `items`（道具区）。
- 私密信息**不做隐藏标记**，state 永远全量；对外可见性由 `core/redact.ts` 的 `redactState(state, viewerId)` 裁剪（他人手牌/弃牌/删牌/抽牌堆→仅数量），server 分发时逐连接调用。金科玉律 1/2 的执行点在分发层而非状态层。
- 临时特权证 = `passHolderSeat`；`rngState` 内嵌 state。

### 2. Action/Reducer（game/whiteboard.ts）
- `reduce(state, action, config) → 新 state`（纯函数，structuredClone）。
- Action 联合类型：swap / stopSwap / playCards / purchase / skipPurchase / deleteCards / ready / reshape。每步校验阶段与合法性，非法操作抛错。
- **重放 = 初始 seed + 有序 Action 流**：RNG 用 mulberry32，32 位状态存在 `state.rngState`，引擎无任何外部随机源。确定性有测试保证（同种子同 Action 流 → 同结果）。
- 已实现完整 8 阶段推进：抽牌自动完成→换牌→出牌→对决自动结算（白板局用 hand-evaluator 最优 JOKER）→结算发奖→购买→删牌→重整→下一回合；车票达标即终局。

### 3. 时间点框架（core/effects.ts）
- 效果 = `EffectDef { id, source, phase, timing, run(state, ctx) }`，`registerEffect()` 注册进注册表（硬编码路线，无 DSL）。
- reducer 在阶段前/后调 `resolveTiming()` 生成结算队列，排序规则：**来源优先级（事件牌>角色技能>黑市牌>规则书）→ 顺时针距特权证距离**。同玩家同来源按注册顺序（"自己效果任选顺序"的交互留 M2 有需求再加）。
- 效果执行异常隔离到单条，坏卡不毁局。

### 4. 效果签名
- `run(state, ctx)` 直接变更工作副本 state；`ctx = { config, playerId }`。M2 实现首批角色/黑市牌时往注册表塞 EffectDef 即可，引擎骨架不动。

### 附带决策
- `GameConfig`（奖励表/目标票数/各参数）从 server 收敛进 engine `core/config.ts`，server 只保留文件读取与合并——reducer 消费配置与"奖励表可配置"贯通。
- 白板骨架简化点（已在代码注释标注）：宣告交互未做（对决自动结算）、初始构筑未做（M2）、黑市效果结算未做（M2）、购买每人每回合一次决策（完整规则可循环购买到翻面）。
