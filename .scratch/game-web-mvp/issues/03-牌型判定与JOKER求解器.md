# 03 - 牌型判定与 JOKER 赋值求解器

Type: task
Status: resolved

## Question

对决核心是纯函数，规则已完全确定，无需等人：输入 ≤5+ 张有效牌（含 JOKER、芯片改点后的点数花色），输出单一最大牌型与总点数。需要决策的点：

- JOKER 赋值搜索算法（枚举？贪心+回溯？），保证找到全局最大牌型（含六条/七条/同花五条/同花葫芦等"造出的牌型"）；
- 同点数总和时的确定性 tie-break（顺时针特权证距离由引擎层补，本模块只输出牌型+点数）；
- 与芯片改点接口的边界：本模块只吃"已改点"的牌面，改点逻辑归效果层。
- 产出：纯函数模块 + Vitest 全覆盖（用规则书示例做验收用例，如葫芦 39 vs 46 点）。

## Answer

模块落地在 `packages/engine`：

- **牌面类型**（cards.ts）：`Card { rank 2-14 | null, suit, isJoker, id }`，A 恒为 14。芯片改点后的牌面由效果层传入，本模块不做改点、不做越界校验。
- **牌型等级**（hand-evaluator.ts）：15 级数值枚举，严格按规则书 7 节顺序（七条 > 同花六条 > 六条 > 同花五条 > 同花葫芦 > 同花顺 > 五条 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 高牌），输出 `{ category, totalPoints, cards[] }`。
- **单一最大牌型**：出牌 >5 张时（规则效果造出六条/七条），枚举全部 5 张子集 + 整组判六/七条家族取最大——六/七张组合只认六条/同花六条/七条，其余价值必被 5 张子集覆盖，无遗漏。
- **JOKER 求解**：逐张枚举 13 点数 × 4 花色赋值，按 (牌型等级, 总点数) 字典序取最优；双 JOKER 搜索空间 ≤2704 组合，代价可忽略。返回值含赋值后牌面（`wasJoker` 标记）供宣告阶段展示。
- **顺子边界**：23456 最小、10JQKA 最大，A=14 无轮子；同花顺 = 同花∩顺子。
- **少于 5 张**（手牌不足出全部）：仅按重复结构判定，无顺/同花。
- **边界划分**：总点数相同时的特权证距离裁决归引擎层（compareHands 返回 0 即交给上层）。

验收：17 个 Vitest 用例全过，含规则书示例（特型演员 JOKER→J 葫芦 39 点、矿工 JOKER→10 葫芦 46 点、矿工胜出）。
