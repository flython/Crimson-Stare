# 16 - 房间流程修复：离开/解散/返回出口

Type: task
Status: resolved
Blocked by: 15

## Question

用户反馈：创建房间后不能取消，刷新后仍自动回到等待加入界面，且没有后退或取消的入口。根因：协议无 leaveRoom 消息；前端 Lobby 无离开按钮、conn/lobby 界面无返回模式选择出口；token 持久化 + server 自动回房导致用户被困。

## Answer

已修复（2026-08-30，ws-e2e 6 测试全过）：

- **协议**（docs/protocol.md）：新增 `ClientMessage { type: "leaveRoom" }` 与 `ServerMessage { type: "leftRoom"; reason: "left" | "ownerLeft" | "roomClosed" }`。
- **server**（room.ts）：`Room.removeSeat` / `Room.close`（解散清定时器并广播 leftRoom）+ `Manager.handleLeaveRoom`——对局未开始：非房主离开 → 移出座位 + 广播 roomState；房主离开 → 解散房间（全体 leftRoom）；对局已开始：leaveRoom 等同断开（座位保留 + 托管继续，可重连）。
- **前端**：Lobby 未开局时显示「离开房间/解散房间」按钮（发 leaveRoom）、大厅态显示「断开连接」；conn 界面加「返回」；App 收到 leftRoom → 回大厅（room=null, 可再建房）。
- **测试**（红→绿）：2 个新用例——房主离开（A/B 均收 leftRoom，A 可再建房）、非房主离开（房主侧成员减少）。
