# 08 - M2.0 卡池数据管道落地

Type: task
Status: resolved
Blocked by: 06

## Question

06 号票据遗留的「转换脚本 + schema」在首批模板（21 角色 + 52 黑市 + 15 命运 + 36 事件）填回后落地：xlsx → JSON 转换、校验、启动时载入注入引擎。

## Answer

已全部落地（2026-08-30，测试全过）：

- **转换脚本**：新包 `packages/card-data/`（Node/TS + SheetJS + zod），命令 `npm run cards:build`（转换写盘）/ `npm run cards:check`（只校验不写盘）。按列名识别四 sheet，触发时机列解析为 `(phase, timing)` 列表，图片列空则按 `assets/cards/<类别>/<ID>.png` 推导。
- **产物**：`config/cards/{roles,market,fate,events}.json` + `manifest.json`（21/52/15/36，黄边 24 + 简易角色 4 已验证），提交 git。
- **校验分级**：硬错=ID 唯一/必填/zod 结构/触发时机段非法（拒绝写盘）；警告=未识别列/图片缺失。结构层（zod）+ 业务层（validateDefs）双层回归测试 15 用例。
- **类型单一事实源**：`packages/engine/src/cardPool.ts` 定义 CardDef/CardPool，转换脚本 import type 复用。
- **启动载入**：`packages/server/src/cardPool.ts` `loadCardPool()`（缺失/损坏抛错，不静默），server 启动时注入（实测输出「卡池已载入 v…: 角色 21 / 黑市 52 / 命运 15 / 事件 36」）。
- **踩坑记录**：① xlsx 的 ESM 构建无 `readFile` 命名导出，须默认导入；② `import.meta.url` 中文路径 percent-encode 导致 CLI 入口判断失效，须 `fileURLToPath` 解码后再与 argv[1] 比较。
